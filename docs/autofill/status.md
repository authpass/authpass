# AutoFill — where this branch stands

Written 2026-08-10, when work paused to finish the release/signing migration
first. Read [plan.md](plan.md) for the design; this file is only "what is on
this branch, what is proven, and what to pick up next".

## Branch layout

Branched from `main`, and not pushed. The release work this used to be stacked
on — fastlane and match removed, signing against stored profiles — landed in
`main` on 2026-08-10, so the extension's provisioning is already there:
`AuthPass iOS AutoFill AppStore`, in blackbox, listed in
`ios/ExportOptions.plist` and in the `PROFILES` array of `_tools/build-ios.sh`.
See [../apple-signing.md](../apple-signing.md).

## Done

**Phase 0 (spike) — go.** Measured on a physical iPhone XR. A headless
FlutterEngine runs inside the appex and opens a kdbx within the extension's
memory budget. Numbers and traps in [plan.md](plan.md#phase-0).

**Phase 1, the shared foundations:**

- **kdbx.dart** — `TransformedKeyCredentials` + `kdfFingerprint`, so the
  extension opens a vault without running Argon2. Submodule branch
  `autofill-transformed-key`, released as 2.5.0, pinned in `pubspec.yaml` by
  commit ref until it is on pub.
- **biometric_storage** — `darwinKeychainAccessGroup`, so the extension can
  read the keys the app caches. Branch `autofill-access-group`, 5.2.0-dev.1,
  also pinned by ref.
- **eTLD+1 matcher** — `lib/utils/credential_matcher.dart` with a vendored
  public suffix list, 53 tests. Wired into the **Android** autofill path too,
  and it understands KeePass2Android `KP2A_URL*` extra URLs.
- **App-group mirror** — `lib/autofill/`, kept in sync on open, save and
  opt-out.
- **Extension target** — `ios/AuthPassAutofill/`, generated by
  `ios/add_autofill_target.rb`. Debug signs automatically; Release and Profile
  sign manually against `AuthPass iOS AutoFill AppStore`.
- **Provisioning** — bundle ids, app group and capability registered; the
  extension's distribution profile is in blackbox.

Verified 2026-08-10 by a real signed build: the exported `.ipa` embeds
`AuthPassAutofill.appex`, signed `Apple Distribution` with the right profile,
carrying `…autofill-credential-provider` and `group.design.codeux.authpass`.

## Not done

**Phase 2 onwards — the actual feature.** What exists in the extension today is
a *spike*, not a product: `CredentialProviderViewController` loads a fixture
vault and proves the engine boots. There is no picker, no keychain unlock path,
no `provideCredentialWithoutUserInteraction`, no configuration UI.

### The quick-unlock migration is not needed

plan.md lists one, on the assumption that the existing quick-unlock items would
move into the shared access group — and biometry-bound items cannot be moved
after the fact. The implementation went a different way, so nothing moves:

- Quick unlock keeps its own keychain item (`…QuickUnlock`, holding composite
  hashes) and the extension keeps a separate one (`AutofillTransformedKeys`,
  holding transformed keys, in the app group). Different items, different
  contents.
- `Runner.entitlements` gains `application-groups` but **no
  `keychain-access-groups`**. That is what makes it safe: with no such
  entitlement the app's default access group stays the app-id group, so items
  written without an explicit group — every existing quick-unlock item — are
  still found exactly where they were. Adding a `keychain-access-groups` list
  later *would* break them, because the first entry in it becomes the default.

Existing users therefore keep quick unlock untouched, and the transformed key
for a vault appears the first time it is opened or saved with autofill on.

## Things that will bite

- **Do not re-serialize a mirrored vault.** `AutofillMirror.syncFile` copies
  the exact bytes it read or wrote. Saving through kdbx would rotate the KDF
  salt and strand the cached transformed key.
- **Never commit the `dependency_overrides`** in `pubspec.yaml`. The two
  submodules are consumed as pinned git refs, not path deps.
- **`autofill_module/` is a separate Flutter module** built by
  `build_ios_framework.sh` into `autofill_module/build/framework/Release`
  (gitignored). The Xcode target references those xcframeworks; if they are
  missing the generator warns and the extension will not link.
- **`AuthPassAutofill/Fixtures/` is gitignored** — regenerate with
  `dart run tool/generate_test_vault.dart` in `autofill_module/`.
- **Re-running `add_autofill_target.rb` rewrites ~400 lines** of `pbxproj`
  UUIDs and ordering even when nothing changed. It no longer leaks build
  configurations, but expect a noisy diff.
