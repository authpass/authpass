## Repository layout

The git root is a thin wrapper. Nearly all code lives in `authpass/` — **run all Flutter/Dart commands from `authpass/`, not from the git root.**

- `authpass/` — the Flutter app (Dart, plus `android/`, `ios/`, `macos/`, `linux/`, `windows/`, `web/` platform dirs)
- `deps/` — 8 git submodules, several maintained by the same author: `kdbx.dart`, `autofill_service`, `biometric_storage`, `diac`, `analytics_events`, `authpass-cloud`, `package_info_macos`, `clipboard_plugintest`. After cloning: `git submodule update --init`.
- `debian/`, `snap/`, `metadata/`, `_docs/` — packaging and store metadata

Note: `deps/` submodules are normally consumed as *published pub packages*, not path deps. `pubspec.yaml` has many commented-out `dependency_overrides` pointing at `../deps/...` and at absolute paths under `/Users/herbert/dev/`. Uncomment those only when deliberately developing against a local checkout; never commit them enabled.

## Commands

All from the `authpass/` directory.

```bash
flutter run -t lib/env/development.dart
```

**A target is always required.** `lib/main.dart` deliberately throws `Exception('Run some env/*.dart')`; the real entry points are in `lib/env/`.

Android additionally requires a flavor (dimension `hpdist`): `playstore`, `playstoredev`, `fdroid`, `sideload`, `amazon`, `huawei`, `samsungapps`.

```bash
flutter run --target=lib/env/development.dart --flavor=playstore
```

| Task | Command |
| --- | --- |
| Analyze | `flutter analyze` |
| Full CI analysis (string literals + analyze + format check) | `_tools/run_analyse.sh` |
| Format | `dart format .` |
| Unit tests | `flutter test` |
| Single test file | `flutter test test/entry_details_test.dart` |
| Single test case | `flutter test test/entry_details_test.dart -n 'test name'` |
| Tests without the WebDAV docker dependency | `flutter test --exclude-tags=webdav` |
| Integration tests | `flutter test integration_test` |
| Code generation | `dart run build_runner build --delete-conflicting-outputs` |
| Regenerate localizations | `flutter gen-l10n` |

CI mirrors this via `_tools/run_analyse.sh` (analyze workflow) and `_tools/test-coverage.sh` (unit test workflow). The WebDAV-tagged tests need the container in `test/cloud_storage/docker-compose.yaml`; CI runs `bytemark/webdav` as a service on port 10280.

`_tools/flutter_run.sh` resolves the Flutter SDK out of `.dart_tool/package_config.json` rather than `$PATH` — CI scripts use it so they hit the pinned SDK. The pinned version lives in `_tools/_flutter_version.sh` (autogenerated; update via `_tools/_flutter_version_update.dart`).

## Architecture

### Environment → Deps → Provider tree

`Env` (`lib/env/_base.dart`) is the configuration root: feature flags, secrets, OAuth redirect URIs, storage namespace, analytics endpoints. Each build target subclasses it (`development.dart`, `production.dart`, `fdroid.dart`, `web.dart`, `test_driver.dart`) and that subclass's `main()` is the app entry point. Behaviour differences between distributions (F-Droid disables website icon fetching, dev uses `EnvSecrets.nullSecrets`) belong here, as `Env` getters — not as scattered platform checks.

`startApp(Env)` in `lib/main.dart` builds a `Deps` (`lib/bloc/deps.dart`), which constructs the four long-lived blocs — `AppDataBloc`, `Analytics`, `CloudStorageBloc`, `KdbxBloc` — and then publishes everything through a `MultiProvider` in `AuthPassApp.build`. Anything app-wide is reached with `Provider.of`/`context.watch`, not singletons.

### KdbxBloc and FileSource

`KdbxBloc` (`lib/bloc/kdbx_bloc.dart`) is the center of the app: opening, saving, closing, creating and merging kdbx databases, plus quick-unlock (credentials cached in `biometric_storage`). It wraps the `kdbx` package (`deps/kdbx.dart`) — cryptography and file format live there, not in this repo. Open files are exposed as a `ValueStream<OpenedKdbxFiles>`; UI reacts to that stream rather than querying state.

`FileSource` (`lib/bloc/kdbx/file_source.dart`) abstracts *where* a database lives, and is the main polymorphism point: `FileSourceLocal`, `FileSourceCloudStorage`, `FileSourceUrl`, `FileSourceWeb`. When adding storage behaviour, extend `FileSource` rather than branching on platform in the blocs.

`KdbxBlocDelegate` is how the bloc reaches the UI (e.g. reporting a merged sync conflict) without holding a `BuildContext`; the implementation is `KdbxBlocDelegateHandler` in `main.dart`, driven by the global `navigatorKey`.

### Cloud storage

`lib/cloud_storage/` implements `CloudStorageProvider` for Dropbox, Google Drive, OneDrive, WebDAV and AuthPass Cloud. Providers declare their auth style via `UserAuthenticationPrompt` (`OAuthTokenFlowPromptData` vs. `UrlUsernamePasswordPromptData`) and the shared UI in `cloud_storage_ui*.dart` renders the right flow — a new provider should not need its own auth screen.

### Analytics

`Analytics` (`lib/bloc/analytics.dart`) fans out to Amplitude / Google Analytics / Matomo depending on `EnvSecrets`. Events are **generated**: declare them on the `AnalyticsEvents` abstract class and `analytics_event_gen` produces `analytics.g.dart`. Screen views are tracked automatically by `AnalyticsNavigatorObserver`.

### UI

Screens live in `lib/ui/screens/`, reusable widgets in `lib/ui/widgets/`. Screens expose a static `route()` factory that supplies **named** `RouteSettings` — `AnalyticsNavigatorObserver._screenNameFor` asserts (in debug) when a non-popup route has no name, so a new screen without a named route will trip that assert.

## Conventions

### Localization

Translations are managed on Crowdin (<https://translate.authpass.app/authpass>). **Only `lib/l10n/app_en.arb` is edited by hand** — never touch another `app_XX.arb`. `lib/l10n-generated/` is generated output (`flutter gen-l10n`, config in `l10n.yaml`); it is excluded from analysis and should not be edited or reformatted.

In code:

```dart
final loc = AppLocalizations.of(context);  // package:authpass/l10n-generated/app_localizations.dart
```

New user-visible strings must be added to `app_en.arb` with a useful `description`.

### string_literal_finder

`string_literal_finder` flags string literals that should be localized. CI runs it as a CLI from `_tools/run_analyse.sh` (`pub run string_literal_finder --path lib --exclude-path l10n/`). `analysis_options.yaml` *also* registers it as an analyzer plugin via an absolute path under `/Users/herbert/dev/dart/` — that entry only resolves on the maintainer's machine and will need removing or repointing elsewhere.

Non-user-facing literals must be marked, and the codebase does this ~250 times:

- `// NON-NLS` trailing comment on the line
- `nonNls(...)` wrapper around a value or collection
- `@NonNls` annotation on a member

Codebase migration to fully externalized strings is incomplete (issue #78), so CI reports counts rather than failing. Still mark new literals.

### Generated files

`*.g.dart` (built_value, json_serializable, analytics_event_gen), `*.freezed.dart` and `*.mocks.dart` are generated by `build_runner` and are excluded in `analysis_options.yaml`. Edit the source class and rerun build_runner; never hand-edit generated output.

### Analyzer strictness

`analysis_options.yaml` uses `package:flutter_lints`, sets `strict-casts: true`, and promotes `missing_required_param` / `missing_return` to warnings. `todo` is ignored, so TODOs are fine.

Formatting is enforced in CI with `dart format --set-exit-if-changed`, excluding `secrets.dart`, `generated_plugin_registrant.dart`, `.dart_tool/` and `lib/l10n-generated/`.

### Encrypted secrets

Real credentials are GPG-encrypted with [blackbox](https://github.com/StackExchange/blackbox); see `.blackbox/blackbox-files.txt`. `lib/env/production.dart`, `lib/env/secrets.dart` and `test/_testSecrets.json` exist only as `.gpg` in the repo and are decrypted in CI by `_tools/postdeploy.sh` using `BLACKBOX_SECRET`. Without the key, use `lib/env/development.dart`, which supplies `EnvSecrets.nullSecrets` — cloud storage providers requiring OAuth client secrets will not work locally.
